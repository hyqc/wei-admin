## /admin/account/* 全部免鉴权（后端 + 双前端）
- 后端配置：`config.yaml` / `config-dev.yaml` / `docs/config.yaml` 的 `jwt.ignores.post.paths` 用 `/admin/account/*` 通配替换原来的 login/captcha 两项
- 后端代码（两处关键改动，缺一不可）：
  1. `app/middleware/auth.go` 新增 `setOptionalClaims()`：白名单路由**可选鉴权**——带合法 token 照样解析写入 claims（业务能识别用户），无 token / token 非法则直接放行不拦截。否则 `/admin/account/info|edit|password|menu|permission` 拿不到 AccountId
  2. `constant/constant.go` 的 `GetCustomClaims()` 无 claims 时**返回空 `&jwt.CustomClaims{}` 而非 nil**，否则免鉴权访问时 `GetCustomClaims(ctx).AccountId` 会 nil 指针 panic
- 前端（Vue + React）：`api/config.ts` 加 `IgnoreAuthApiPrefixes = ['/admin/account/']` + `IsIgnoreAuthApi(url)`；`api/request.ts` 401 响应分支加豁免——免鉴权接口不再强制 Logout。**仍照常注入 token**（不注入会导致后端识别不到用户）
- 验证：无 token 调 `/admin/account/info` → `code:1 record not found`（已放行、未 panic），带非法 token 同样放行；对照 `/admin/user/list` 无 token → `200003 登录令牌检查失败`（鉴权仍在）；两版 `tsc/vue-tsc` 均 0 错误

## 无权限不再强制登出（用户要求）
- 后端码值（proto/code_proto/error_code.pb.go）：200001 鉴权失败、200002/200003 token 无效、200004 token 信息无效、**200005 没有访问权限**；均走 HTTP 200 + body.code（后端 `code.JSON` 不改 HTTP 状态码）
- 两版前端 `api/code.ts` 新增 `AuthErrorCode`（200001~200005）+ `IsAuthTokenInvalidCode()`（令牌失效，需重登）+ `IsAuthForbiddenCode()`（无权限，仅提示）
- `api/request.ts`：响应拦截器业务码分支——**只有令牌失效类才 Logout**；200005 仅 `message.error('没有访问权限')`。reject 值改为携带 `code` 的 Error（`RequestError = Error & { code?: number }`，Vue 版原是字符串，项目内 catch 均忽略参数，无兼容问题）
- 路由守卫（Vue `router/index.ts`、React `ProtectedLayout.tsx`）：`fetchUserInfo()` 失败时，若 code=200005 → 跳 `/403` **不登出**；否则才 Logout + 跳登录（带 redirect）
- 注：HTTP 401 分支保持登出（免鉴权接口除外，见上一条）

## 个人中心邮箱改为非必填
- 前端（Vue `views/account/components/CurrentAccount.vue`、React 同名 tsx）：邮箱规则去掉 required，改为自定义 validator —— **空值直接放行**（`if (!value) return resolve()`），有值才用 `AdminEmail.test()` 校验。注意：不能只删 required 保留 `pattern`，async-validator 对空字符串也会跑 pattern 而报错
- 后端：`proto/admin_proto/admin_account.proto` 的 `ReqAccountEdit.email` 由 `binding:"email"` 改为 `binding:"omitempty,email"`（与 admin_user.proto 中账号新增/编辑的写法一致）
- **重大教训：本机没有 `protoc-gen-gotags` 插件**（只有 protoc-gen-go/go-grpc/gogofaster/govalidators/micro）。用 `protoc --go_out` 重新生成 .pb.go 会**丢失所有 `binding`/`label` struct tag**（只剩注释里的 @gotags 文本），导致后端参数校验全部失效
  - 正确做法：改 .proto 后**不要重跑 protoc**，直接手动编辑对应 .pb.go 的 struct tag（`protobuf:... json:... binding:"..." label:"..."`）
  - 本次误生成后已手工补回 admin_account.pb.go 的 11 个字段 tag，并用登录空参数验证校验生效（返回 `300003 验证码ID为必填字段`）
